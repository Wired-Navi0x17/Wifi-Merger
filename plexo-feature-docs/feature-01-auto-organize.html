Plexo Feature Report 01:
Automatic File Organization by Type

Single-file HTTP downloads are sorted into category folders at download time, with user-customizable buckets and two ways to sort a folder that already has loose files: a button in the app and a Python script.

Version 1.1, 2026-10-17. Scope: HTTP single-file downloads only. Torrents are excluded from organizing by design. Supersedes version 1.0 of 2026-10-16.
Print instruction: open this file in a browser and press Print to PDF, A4, margins default, background graphics on. This banner does not print.

1. Executive summary

Problem. Every Plexo download landed flat in one destination folder. Documents, videos, archives and installers piled together, and the user sorted them by hand.

Solution. Feature 1 adds automatic file organization. At download start the engine resolves a category folder from the file extension (for example Videos/ for .mp4), creates it on demand inside the picked destination, and claims the final name there. In the Auto organize dialog (Downloads screen) users can rename buckets, edit extension lists, point a bucket at a custom folder, switch organizing off globally, and press Organize a folder now to sort files that are already sitting in a folder. The same rules are available from the command line through scripts/organize.py, and the app passes its current buckets to the script so a renamed bucket sorts the same way everywhere.

Result. New downloads arrive pre-sorted, and existing messy folders are fixed either from the dialog or with one scan command. Verification: three Playwright organization tests pass (organized landing, per-download opt-out, preview without downloading), the 20-test engine suite and the 10-test UI suite still pass, Python and TypeScript collision rules were checked for parity, and all four typecheck projects exit 0.

2. What is new

2.1 Default buckets

Category Default folder Extensions
Documents <destination>/Documents/ pdf, doc, docx, txt, md, rtf, odt, xls, xlsx, ppt, pptx, csv
Videos <destination>/Videos/ mp4, mkv, mov, avi, webm
Archives <destination>/Archives/ zip, rar, 7z, tar, gz
Programs <destination>/Programs/ exe, msi, dmg, deb, rpm, appimage
Others <destination>/Others/ catch-all: unknown or missing extensions

2.2 User control

  • Global on/off switch in the Auto organize dialog (Downloads screen).
  • Rename buckets: each bucket has a Name field (1 to 40 characters). The name is also the default subfolder name, so renaming Videos to Clips sends new videos to Clips/.
  • Per-category extension editing (comma separated, case-insensitive, leading dots stripped; up to 64 extensions of up to 16 characters each).
  • Per-category custom folder: blank means the default subfolder; absolute path moves that bucket elsewhere.
  • Organize a folder now button: pick any folder, Plexo runs the scan with your current buckets and reports how many files moved.
  • Per-download override in New Download: checkbox plus live preview of the final path (for example .../Videos/demo.mp4). Torrents show no organize row.
  • Reset to defaults button restores the table above.

3. Background (short network context)

Plexo is an Application layer (OSI L7) download manager that multiplies throughput with many Transport layer (L4) TCP connections pinned to distinct Network layer (L3) paths. This feature sits above that engine: it does not change how bytes arrive, only where finished files land. The split, hedge, peer spread, and speed limit machinery are untouched. The hook point is narrow: destination resolution at download start, plus a post-hoc batch mover.

4. How it works

4.1 Resolution rules (TypeScript, src/main/download/organize.ts)

  • Extension is lowercased text after the last dot; archive.tar.gz maps to gz; dotfiles and trailing dots map to the catch-all bucket.
  • First matching bucket in order wins. The catch-all is the first bucket with an empty extension list (Others by default), falling back to the last bucket in the list if the user deleted it.
  • Folder override: absolute paths stay absolute; plain names become subfolders of the destination; .. escapes and illegal names fall back to the default label folder.
  • The bucket folder is created on demand (with the same helper downloads use), free space is checked there, and the existing name claim runs inside that folder, so collisions (name (1)) and staging (.plexo) behave exactly as before.
  • The download manager decides per download: organize = request.organize ?? settings.autoOrganize.enabled ?? true, so a fresh install organizes by default and the New Download checkbox wins over the global switch.

4.2 Python automation (scripts/organize.py, stdlib only)

  • --dry-run --base-dir DIR --filename NAME prints the computed JSON target, used by tests and mirrors.
  • --move PATH [--base-dir DIR] moves one finished file into its bucket with the same collision loop.
  • --scan DIR [--config FILE] sorts every loose file at the top level of a folder; *.plexo staging files are never touched, and directories are left alone.
  • --config takes {"categories": [...]}. The app uses this: pressing Organize a folder now writes the user's current buckets to a temp file and passes it, so renames, custom folders and edited extension lists apply. Without a config the script's built-in defaults (the table above) are used.
  • Collision parity with the TypeScript claim (paths.ts claimName): only the last extension is kept last (a.tar.gz becomes a.tar (1).gz), and an extension longer than 32 bytes is treated as part of the name.

4.3 Settings, IPC, and UI

  • Settings live in app-settings.json (under the OS user data folder) as AppSettings.autoOrganize. Validation is per entry: a bucket id must be 1 to 32 lowercase letters, digits or dashes, a name 1 to 40 characters after trimming, extensions become unique lowercased tokens, a relative folder must match [A-Za-z0-9 _.-] up to 64 characters, an absolute folder up to 512. A bad entry only loses itself, never the whole block.
  • IPC: organize:preview-path (pure preview, returns the predicted path or null) and organize:folder-now (runs the scan, returns {count}), plus typed preload bindings; start requests carry an optional per-download organize flag.
  • UI: OrganizeDialog.tsx (draft on open, single save, rename field, scan button), New Download checkbox with live preview, store field autoOrganize seeded from InitialState.

6. Limitations and roadmap

  • Torrents are excluded by requirement; multi-file folder classification is future work.
  • Classification is by extension only, not by file content sniffing; a misnamed file follows its suffix.
  • The scan sorts the top level of the chosen folder only; it does not descend into subfolders.
  • Custom absolute folders are trusted as typed (up to 512 characters); network drives must be mounted first (existing destination check applies).
  • Roadmap slots: content-aware buckets, per-site rules, scheduled tidy runs, an undo log for batch scans, scanning subfolders.

Appendix A. Demo script (5 minutes)

  1. Open Downloads, press Auto organize, confirm defaults and enabled.
  2. Rename the Videos bucket to Clips in the Name field, press Save, reopen the dialog and show the name stuck.
  3. New Download an MP4 link, note preview .../Clips/<name>, start, show the file in the folder.
  4. Repeat with a PDF, note .../Documents/.
  5. Uncheck organize on a third download, note flat save.
  6. Prepare a messy folder, press Organize a folder now, show the moved count and the sorted result (the button uses your current buckets, so the Clips rename applies). Optionally show the CLI: python3 scripts/organize.py --scan ~/Downloads/messy.
