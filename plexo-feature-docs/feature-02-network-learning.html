Plexo Feature Report 02:
Learning from Network Behaviour

Per-host and per-network profiles plus a Gaussian Thompson Sampling tail strategist. The deterministic engine still executes every download. The learner only advises tail strategy, inside hard caps, with an off switch and a forget button.

1. Executive summary

Problem. Some servers limit each connection (per-connection throttling). Near the end of a download, one slow tail block can hold the whole file while idle streams wait, because the fixed rules (hedge after 2 s, start 8 streams) assume an average server. An open Plexo issue documents this tail stall on such servers.

Solution. Plexo keeps persistent local profiles per download source and network (throughput and tail length as moving averages, retry totals) and a Gaussian Thompson Sampling bandit over three tail strategies: conservative (4 streams, hedge after 4000 ms), standard (8 streams, 2000 ms, today's default) and aggressive (16 streams, hedge after 1000 ms). While any arm is untried, one of the untried arms is picked uniformly, so all three get a first run. After that each arm samples from its posterior, the best draw wins, and a 10 percent epsilon floor keeps exploring. Acting is fenced: hedge timing stays within 1000 to 4000 ms, starting streams within 4 to 16, server ceilings, disk caps, user picks and per-block hedge caps still win, and the whole advisor is off by default (record-only) until enabled in the new Learning dialog, which also has a Forget learned data button.

Result. Recording and arm selection are verified end to end: 14 learning tests pass, including two downloads from a throttled origin that complete and are recorded, an activated run that selects an arm and persists updated beliefs, and a fixture download with PLEXO_DEBUG=1 that logs arm choice and outcome. The 20-test engine suite and the 10-test UI suite still pass, and all four typecheck projects exit 0.

2. Background: the tail problem in one paragraph

A Plexo HTTP download splits a file into blocks fetched by parallel TCP streams. When blocks remain, every stream has work. When only slow blocks remain, free streams hedge them (re-fetch the same range, first finisher wins). Fixed hedge timing is a compromise: too early wastes bytes on healthy servers, too late stalls on throttled ones. The learner personalizes this compromise per host and network kind from observed history instead of guessing once for all servers.

3. Design

3.1 Profiles (learning/profiles.ts)

Per host: download and completion counts, throughput and tail length as exponential moving averages (weight 0.3 per sample), a time-to-first-byte average, retry totals, stall counts and status-code refusal counters (403, 429, 503, other). Per network: a throughput average, stall count and download count. A host with 2 or more downloads and 3 or more refusals plus retries reads as rate-limited (looksRateLimited). Honest note: in this build the engine reports first-byte time and stalls as 0, and nothing increments the refusal counters yet. Those fields are recorded for completeness; the moving averages only update on positive samples, so they stay 0 until the wiring lands. The reward in the next section uses the signals that are live today: completed, tail duration and retries.

3.2 Bandit (learning/bandit.ts)

Gaussian Thompson Sampling over three arms. Choice: if any arm has zero pulls, one of the untried arms is picked uniformly, so every arm is tried before posterior sampling starts. Otherwise, with probability 0.1 (epsilon) a uniformly random arm is picked to keep exploring; the rest of the time each arm is sampled once from its Gaussian posterior (mean and sample variance from a Welford update, variance floor 0.01) and the highest draw wins. Reward: a failed run scores -2; a completed run scores clamp(saved * 2 - retryCost, -2, +2), where saved = (expectedTailMs - tailMs) / expectedTailMs, expectedTailMs = max(host average tail, 1000) and retryCost = min(retries / 10, 1). The tail is measured from the moment the last pending block is taken into work until the run ends. Method follows Agrawal and Goyal 2012 (Thompson Sampling); reference implementation consulted: PyPI thompson (MIT, Erdogan Taskesen). The code is an independent, dependency-free port, attributed inline. No model download, no API, no network use.

3.3 Context (learning/context.ts)

Key is host|network-kind|size-band|range-flag (for example example.com|wifi|s|r). The host is lowercased with port and brackets stripped; anything that isn't a plausible host becomes unknown. Size bands: small below 10 MiB, medium up to 500 MiB, large above (unknown size counts as large). Small enough for a host to get repeat visits (learning needs repeats), specific enough to matter: a host throttling phones but not Wi-Fi learns two lessons.

3.4 Safety rails and controls

  • Record-only is the default. Acting needs settings.learning.tailAdaptive, which the Learning dialog (Downloads screen) writes, or an edit of app-settings.json by hand. The setting validator keeps only true; off means the key is absent.
  • Forget learned data in the same dialog calls a learning:reset IPC that clears every profile and belief and saves an empty store.
  • Suggestions are clamped (hedge 1000 to 4000 ms, streams 4 to 16 done with integer floors). User stream picks and test knobs have priority over the learner, and existing per-block hedge limits still apply.
  • With the switch off nothing reads the beliefs: the transfer asks for a suggestion, gets null, and uses the unchanged default policy.
  • Learning never throws into a download; corrupt stores fall back to empty.

6. Limitations and roadmap

  • Acting phase is tail-only: startup streams and hedge timing. Peer spread and block size stay heuristic until measured wins justify more.
  • First-byte time, stalls and refusal counters are recorded fields with no live wiring yet (they read 0); the defined rate-limit flag is unit-tested but the runtime does not consult it today. The reward uses tail duration and retries, which are live.
  • Evidence uses the scripted test origin (deterministic throttling and request checking), not a real throttling CDN; field trials come next.
  • Torrents record nothing yet; the same profile shape is reserved.
  • Roadmap: enable tail-adaptive by default after field wins, LinUCB context upgrade, tiny local inspector UI. The undoable store reset shipped in this version as the dialog's Forget button.

Appendix A. Demo script (5 minutes)

  1. Open the Learning dialog from Downloads. Show the toggle off (default) and the explanation text.
  2. Run two downloads of sample.pdf from the local fixture server (or any small file). Open learning.json afterwards and show the host entry grew while nothing about the downloads changed (record-only).
  3. Toggle on, run another download with PLEXO_DEBUG=1, and show the console lines [plexo] learn choose and [plexo] learn outcome plus the updated beliefs in learning.json.
  4. Press Forget learned data, reopen the file, show it was emptied.
