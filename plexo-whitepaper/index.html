Whitepaper for CS2403 Computer Networks, version 2.0, date 2026-10-16

One file. Many networks. One fast download.

Plexo lives at OSI Layer 7. It opens many TCP connections at Layer 4. It pins each one to its own IP path at Layer 3. Then it merges the parts back into one file.

L7
Application layer is home: HTTP Range, BitTorrent, DNS, cookies
L4
Transport layer is the engine: TCP sockets, ports, seq numbers, windows
L3
Network layer is the steering: IPv4 and IPv6, routing, source IP, device bind

30 second summary

  1. You have Wi-Fi plus phone data. Each path alone is slow.
  2. Plexo asks for bytes 0 to 8M through Wi-Fi and bytes 8M to 16M through phone, at the same time.
  3. Both TCP streams land at exact file offsets. The merge is byte exact.
  4. For torrents, peers spread across networks by fewest peers first.
  5. Conflicts are handled: same subnet warns, dead route retires, changed file aborts safely.

Section 1: Problem statement

One pipe is slow. Two pipes sit idle.

A normal app opens one TCP connection. That one connection has one congestion window, one round trip limit, and one ISP cap. Your second interface does nothing.

OSI layers, with real network terms

Every byte travels down 7 OSI layers on send and back up on receive. Each layer adds its own header. Each layer speaks its own unit: message, segment, packet, frame, bits. Click each layer for the full story.

L7 Application

PDU: data and messages

Protocols: HTTP/1.1 Range, BitTorrent wire, DHT, tracker HTTP, DNS names. Plexo sends GET with Range: bytes=s-e and expects 206 Partial Content plus Content-Range. Section 3: Proposed solution

Find, pin, fetch, merge

Four moves repeat for every download: find networks, pin sockets, fetch parts, merge bytes. Each move has guards against conflicts (next section).

Step A: find networks (L2 info, L3 addresses)

Call os.networkInterfaces. Drop internal, 169.254.x.x, fe80. Compute subnet with IP AND mask. Name cards per OS: networksetup on macOS, Get-NetAdapter on Windows, name regex on Linux. Poll each 1000 ms. No OS event exists for plug, so poll is required.

Live demo: unplug simulation

Wi-Fi wlan0192.168.1.5 / 255.255.255.0subnet 192.168.1.0/24, gw 192.168.1.1on
Phone usb0192.168.42.10 / 255.255.255.0subnet 192.168.42.0/24, gw 192.168.42.129on

Both on with own gateway, so gain is real. Shared gateway would mean no gain.

Step B: pin sockets (L4 plus L3)

Mac and Windows route by source IP, so localAddress is enough. Linux picks exit from the routing table only, so Plexo also calls setsockopt with SO_BINDTODEVICE through koffi libc. It passes both device and source IP because one card can hold many IPv6 addresses. Loopback skips bind.

connectRoute({ device: wlan0, localAddress: 192.168.1.5, remoteAddress: 93.184.216.34 }, 443)
Linux: fd = socket(AF_INET, STREAM) then setsockopt(SO_BINDTODEVICE, wlan0) then connect()
Happy Eyeballs: race v4 vs v6 with 250 ms stagger, cache winner in lastGoodRoute

Step C: HTTP fetch with Range (L7)

Probe GET bytes 0 to 1023. Status 206 means split. Status 200 means single stream. Cut into 1 to 8 MB blocks. Start 8 streams per net, grow to 32 on health, cut on 403, 429, 503 or disk behind. Hedge the tail so one slow block cannot hold the file.

Lab 5: splitter plus parallel fetch

Target equals nets x 32 x 2. Clamp 1 to 8 MB.

Lab 6: hedge race at the tail

Hedge starts only when zero pending blocks remain, attempts older than 2 s, max 2 hedges per block.

Slow
Hedge

First to finish wins. Loser gets abort reason lost.

Step D: torrent fetch (L7 swarm)

Patched webtorrent routes every outbound TCP peer through connectRoute. New peer picks the network with fewest peers. Max 30 peers per net. Inbound peers map by localAddress. Piece bytes stay provisional until hash verifies, then credit splits proportionally across contributors.

Section 3b: Deep merge (how two networks become one file)

Merge is byte exact, not speed sum

Speeds add. Bytes never double count. HTTP merge key is file offset. Torrent merge key is verified piece hash. Both keep per network tallies that always sum to the true total.

Lab 8: HTTP offset merge

Press Play merge. Wi-Fi takes even blocks, phone takes odd blocks. Watch frontier grow and per net counters stay exact.

Frontier: 0 / 12 blocks Wi-Fi bytes: 0 Phone bytes: 0

Rule: frontier equals max progress, not sum. Overlap bytes count once. Code: advanceBlock and retractBlock in blockProgress.ts.

Section 5: Conclusion and roadmap

Merge at L7, pin at L4, steer at L3, observe L2 and L1

That one line is the whole design. Plexo never claims magic. If paths share a bottleneck, it says so. If a server refuses split, it falls back to one stream.

Next tests

  1. Throughput: Wi-Fi plus USB tether, 100 MB to 1 GB, Plexo on versus off.
  2. Failover: unplug mid file, measure stall gap and resume offset.
  3. Fairness: 4 concurrent downloads sharing 32 streams per net.
  4. Power: socket count versus battery drain on laptop.
